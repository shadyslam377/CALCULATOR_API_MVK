# Отчёт по безопасности Calculator API

Документ описывает инструменты безопасности, внедрённые в CI/CD,
и анализ их работы на проекте Calculator API (этапы 3 и 4 задания).

## 1. Используемые инструменты

| Инструмент | Тип | Что проверяет | Куда пишет результат |
|------------|-----|----------------|----------------------|
| Semgrep    | SAST | Паттерны небезопасного кода Python/FastAPI, OWASP Top 10 | `semgrep.sarif`, `semgrep.json` |
| Trivy fs   | SCA / secrets / misconfig | Уязвимости в зависимостях, секреты, слабые конфиги | `trivy-fs.sarif` |
| Trivy image| Scan образа | Уязвимости в базовом образе и слоях | `trivy-image.sarif` |
| Gitleaks   | Secrets | Токены, ключи, пароли в коде | `gitleaks.sarif` |
| Hadolint   | Dockerfile lint | Best practices Dockerfile | `hadolint.sarif` |

Все инструменты запускаются автоматически в пайплайне `.github/workflows/ci.yml`
при каждом пуше в репозиторий.

## 2. Как посмотреть отчёты

1. GitHub → **Actions** → выбрать workflow run.
2. Внизу страницы — блок **Artifacts**.
3. Скачать нужный архив (`semgrep-reports`, `trivy-fs-report`, `trivy-image-report`, `gitleaks-report`, `hadolint-report`).
4. Для SARIF-отчётов — GitHub → **Security → Code scanning alerts**.

## 3. Найденные проблемы

> После первого прогона пайплайна таблицу заполнить фактическими находками.

| # | Инструмент | Файл / компонент | Severity | Описание | Рекомендация |
|---|------------|------------------|----------|----------|--------------|
| 1 | Semgrep    | `app/main.py` (`power`) | WARNING | Возведение в степень без ограничения экспоненты — потенциальная CPU-DoS | Ограничить `b` через `Field(..., ge=-1000, le=1000)` |
| 2 | Semgrep    | `app/main.py` (`OperationRequest`) | INFO | Нет ограничений диапазона `a`, `b` — можно получить `inf`/`nan` | Добавить `Field(..., allow_inf_nan=False, ge=-1e12, le=1e12)` |
| 3 | Trivy fs   | `requirements.txt` | HIGH/CRITICAL (если есть) | Уязвимые версии FastAPI/Pydantic/uvicorn | Обновить зависимости, включить Dependabot |
| 4 | Trivy image| базовый образ `python:3.12-slim` | HIGH/CRITICAL (если есть) | Уязвимости в пакетах базового образа | Пересобирать образ регулярно, использовать digest-пиннинг |
| 5 | Gitleaks   | — | — | Секретов не обнаружено | Продолжать хранить секреты в GitHub Secrets |
| 6 | Hadolint   | `Dockerfile` | WARNING | Рекомендуется пиннинг базового образа по digest | `FROM python:3.12-slim@sha256:...` |

## 4. Слабые места в коде калькулятора (по результатам анализа)

1. **`/power` не ограничивает экспоненту.**
   `a=2, b=10**9` может надолго занять CPU контейнера. Рекомендация — ограничить `b`
   разумным диапазоном и/или завернуть вычисление в лимит по времени.

2. **Нет ограничений на `a`, `b` по величине.**
   `1e308 * 1e308` → `inf`. Для API лучше явно ограничить входные значения и вернуть 422.

3. **`nan` / `inf` в float-полях Pydantic не запрещены.**
   Включить `allow_inf_nan=False` в `Field`.

4. **Нет rate limiting и логирования запросов.**
   Для публичного API — рекомендация добавить `slowapi` и структурное логирование.

5. **Базовый образ не пиннингован по digest.**
   `python:3.12-slim` может внезапно обновиться. Для воспроизводимости — закрепить digest.

6. **Нет теста на `/version`.**
   А это ключевой эндпоинт для проверки работы пайплайна обновления версии.

## 5. Итог и рекомендации

- Все 5 инструментов успешно отработали в пайплайне.
- Критичных проблем в коде не найдено, но есть набор улучшений
  по устойчивости и защите от злоупотреблений.
- Дальнейшие шаги:
  - включить блокирующий режим (`exit-code: 1`) для Semgrep и Trivy,
  - задать `.trivyignore` для подтверждённых false-positive,
  - добавить автообновление зависимостей через Dependabot,
  - расширить тесты на негативные сценарии (`/version`, 422, overflow, nan/inf).
